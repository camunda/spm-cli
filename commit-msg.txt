test(schema): hold the manifest model against the ai.json schema

The JSON schema and the serde model in src/manifest.rs describe the same
ai.json shape by hand; only the targets enum was guarded. Add a parity
test (src/manifest/schema_parity.rs) that checks both layers declare the
same fields, accept a valid corpus that round-trips through save, and
reach the same verdict on cases generated by mutating a fully-populated
manifest node by node (wrong types, unknown and missing keys, conflicting
selectors, empty strings and arrays, duplicate items) plus hand cases.
Rules only the model can enforce are listed in an explicit allow-list
that fails on stale entries.

The test found real mismatches, fixed in the model:
- `$schema` was dropped whenever spm rewrote ai.json;
- unknown keys, explicit nulls and positional arrays were accepted;
- targets (empty, unknown, duplicate), duplicate allowedSources, empty
  strings and malformed commits were only rejected by the schema.
Spec field checks now live in one SkillSpec::validate shared by root and
nested manifests, so a nested spec rejects unknown keys and nulls too.

Also guard the targets table in docs/guide/targets.md against the
targets the CLI accepts.
